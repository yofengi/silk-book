# 版本检查与发布

应用使用公开仓库 [yofengi/silk-book](https://github.com/yofengi/silk-book) 的 GitHub Releases。用户无需提供 GitHub 凭据。

## 用户行为

设置导航的“关于”位于“快捷键”下方，显示当前版本、GitHub 入口、手动检查更新和检查间隔。

| 间隔 | 后台检查周期 |
| --- | --- |
| 默认 | 每 24 小时 |
| 随时 | 每小时 |
| 每周 | 每 7 天 |
| 每月 | 每 30 天 |

启动后延迟检查，不阻塞编辑器加载；到期时间持久化，多个窗口共享检查状态。手动检查不受后台间隔限制。

后台发现更高的稳定版本时，顶栏显示下载图标。用户可查看更新说明、下载当前系统及架构的安装包，或忽略该版本。忽略记录只隐藏相应版本的后台提示，手动检查仍可查看；后续新版本会重新提示。

0.2.0 起，更新包在应用后台下载，关于页和顶栏同步显示下载字节数与进度；关闭更新弹窗后继续下载。自动更新开关默认关闭，开启后只自动下载，不自动安装。手动更新可选择“仅下载”或“下载并安装”，默认仅下载。自动下载和手动“下载并安装”完成后，会在一个窗口中展开安装提示；两种手动模式都必须再次点击安装按钮。

下载完成后，安装按钮替换“下载更新”和“忽略这次更新”。点击安装时，每个窗口都会等待正在进行的文件操作，检查未保存内容并写入设置；保存失败或任一窗口取消，就恢复全部窗口的编辑。全部同意后开始安装并重启。Windows 使用静默 NSIS 升级，macOS 使用官方 Tauri updater 替换应用包；无目录写入权限时，macOS 可能要求系统授权。

已验证的更新包保存在应用自己的缓存目录，重启后仍可安装。重启后安装需要联网确认该版本的发布清单，不会重复下载安装包；网络错误或安装失败可以重试。已成功升级的更新缓存会清理，不会删除用户“下载”目录中的安装包、编辑文件、设置或主题。下载未完成就退出应用时，下次重试从头下载。

0.1.x 仍通过浏览器下载，首次升级到 0.2.0 需手动运行本次安装包。macOS 请将应用放入 Applications 后使用应用内更新；不支持直接在只读 DMG 中替换应用。

0.2.1 起，应用内确认框跟随当前主题，默认聚焦取消；其他窗口取消退出或安装时，会关闭相应的过期确认框。Windows 安装器保存已选择的关联类型，保留数据卸载后再安装会恢复这些注册；主动取消注册或明确不关联任何类型的选择也会保留。旧版本已经删除且没有保存记录的关联需重新注册一次。

## 发布约定

- 版本保持 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 一致，使用 `v0.1.0` 形式的 tag。
- 应用查询 `/repos/yofengi/silk-book/releases/latest`，比较稳定语义版本；草稿与预发布不作为正式更新。
- 安装包名称包含平台和架构：`silk-book-<version>-windows-x64-setup.exe`、`silk-book-<version>-macos-arm64.dmg`、`silk-book-<version>-macos-x64.dmg`。
- GitHub Actions 的 `Build installers` 工作流先生成原生安装包和校验文件，验证完成后再发布正式 Release。
- 同时发布 Windows `.exe.sig`、macOS 两种架构的 `.app.tar.gz` 和 `.sig`，以及三平台齐全的 `latest.json`。每个更新包都使用固定公钥校验签名，签名也绑定版本；缓存恢复与安装前重新验签。
- 网络失败、尚无正式发布、当前平台没有安装包和已经是最新版本分别显示，不能互相替代。

## 平台状态

Windows 设置目录沿用 `%APPDATA%/Boshu`。macOS 使用 `~/Library/Application Support/Boshu`。尺寸记忆由常规页的“记住窗口大小”开关控制，默认启用。

macOS 产物在 macOS runner 构建并检查临时签名；正式 Apple 开发者签名和公证需要维护者另行配置凭据。
